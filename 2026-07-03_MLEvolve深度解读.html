在 MLE-Bench 上以 一半的时间预算 拿下 65.3% 平均奖牌率，全面超越 AlphaEvolve、AIBuildAI 等 SOTA 方案

1一句话总结

MLEvolve 是一个 基于 LLM 的自进化多智能体框架，专门用于端到端机器学习算法发现（MLE）。它通过三项关键设计——渐进式蒙特卡洛图搜索（Progressive MCGS）、回溯记忆（Retrospective Memory）与规划-编码解耦的自适应生成机制——首次同时解决了 MLE 智能体的三大顽疾：分支间信息孤岛、无记忆搜索、层级控制缺失。

2问题背景：现有 MLE Agent 卡在哪里？

LLM 智能体正被广泛用于科研发现与机器学习工程（MLE）这类长时段任务。但作者指出，现有方法（AIDE、R&D-Agent、AIRA-Dojo、MLE-STAR、FM-Agent 等）在长时段自进化时普遍存在三个瓶颈：

痛点 1

分支间信息孤岛

传统 MCTS 只能在同一分支往深处走，不同分支之间无法互相借鉴——一个分支已经踩过的坑，另一个分支还得重新踩。

痛点 2

无记忆搜索

Agent 每一步的经验（成功技巧、失败教训）用完即弃，无法沉淀为可复用的先验，导致长时段迭代收益递减。

痛点 3

缺乏层级控制

规划与编码耦合在一起，往往陷入"改一小段代码却把整个 pipeline 打乱"的稳定性问题，无法稳定地长时间迭代。

"Existing MLE agents suffer from inter-branch information isolation, memoryless search, and lack of hierarchical control, which together hinder long-horizon optimization." —— 论文摘要

3方法论：三大核心组件如何协同

① Progressive MCGS：从 MCTS 到有向图搜索

作者把经典 MCTS 扩展成 有向图 G=(V, E)，其中 E = ET ∪ Eref：

  • 主边 ET：父子生成顺序，用于选择与回溯（等价传统 MCTS）
  • 参考边 Eref：跨分支或非相邻的知识流动通道，让不同分支之间可以组合迁移；不参与回溯，避免污染价值估计
  • 当 Eref=∅ 时，MCGS 退化为标准 MCTS——即向下兼容

渐进探索调度（Entropy-Inspired Progressive Schedule）：UCT 探索系数 c(t) 从 c0 衰减到 cmin，同时用 Shannon 熵 H(πt) 度量各分支的选择频率。软切换机制以概率 w(t) 在 UCT 探索 与 Elite-Guided 利用 之间过渡：

四类扩展操作

① 主扩展（R=∅）；② 分支内演化（同分支最近 k 个节点）；③ 跨分支参考（分支停滞时召唤其他分支 top-N）；④ 多分支聚合（全局停滞时综合多分支洞察，创建新根）

两级停滞检测

分支级 τbranch 步无提升 → 触发分支内演化，再触发跨分支参考；全局级 τglobal 步无提升 → 触发多分支聚合，破除局部极值

模拟奖励 R(v)

失败 = -1；成功但未刷新分支最佳 = 1；刷新分支最佳 = 2

② Retrospective Memory：给 Agent 一个能长期成长的"大脑"

冷启动

领域知识库

静态，按任务类型（图像分类、NLP、表格回归等）组织，包含开源项目 + 竞赛平台沉淀的候选模型与使用指南

动态成长

全局动态记忆

每次有效执行后写入 (plan, outcome, analysis, feedback) 四元组；混合检索：BM25 关键词 + FAISS 语义，用 Reciprocal Rank Fusion (RRF) 融合

阶段感知检索：规划阶段用当前 plan 作为查询，同时召回成功与失败案例；调试阶段用报错信息作为查询，直接找出历史踩坑经验。

③ 分层规划与自适应代码生成

把 Planner（模块级：改什么、为什么）与 Coder（代码级：怎么改）解耦，Coder 提供三种自适应生成模式：

Base 模式

从零全量生成

初始草稿，适用于开局或大结构重写

Stepwise 模式

按模块顺序生成

跟随 Planner 拆分，适合复杂多阶段 pipeline

Diff 模式

局部差异化编辑

在已能跑通的解上做定向精修，不破坏其他部分

6深度分析：这篇论文真的是"突破"吗？

它做对了什么

  • 结构化搜索胜过暴力堆算力。MCGS 通过参考边打通分支间信息通道，从数据结构层面根治了 MCTS 的分支孤立问题——这是方法论层面的贡献，而不是简单的工程优化。
  • 把"记忆"当作一等公民。Retrospective Memory 结合冷启动知识库和动态全局记忆，让 Agent 在长时段迭代中真正有"经验积累"，不再是"每一步从零开始"。
  • 规划-编码解耦解决稳定性问题。Adaptive Code Generation 的三种模式让 Agent 可以在"重写"和"精修"之间自主切换，这是长时段迭代能稳定收敛的关键。
  • 跨领域验证。不仅刷 MLE-Bench，还在数学优化上打败 AlphaEvolve——证明框架具备真正的通用自进化能力。

可能的局限与需要审慎看待的地方（论文正文中未见明确 Limitations 章节，以下是解读者的独立评估）

  • 骨干模型强依赖。使用 Gemini-3.1-Pro-preview 这一未公开发行的顶级模型，其它团队复现时能否保持同等性能存疑。置信度：中
  • 成本未披露。论文未给出总 token 消耗与 API 成本，"12 小时预算"的经济性无法评估。
  • H100/H200 单卡设定。MLE-Bench 中真正需要大规模训练的任务本身受硬件限制，这个设定与真实 Kaggle 竞争者的算力有显著差距。
  • 对比方法的时间不对等。基线大多是 24 小时预算，但骨干模型代际不同（o1-preview vs. Gemini-3.1-Pro-preview 有明显模型能力差）——严格公平比较应控制骨干变量。值得存疑
  • 数学优化任务对比 AlphaEvolve 的具体数字论文正文（本次抓取的 HTML 版本）未详细展开，只在 Abstract 中提及"outperforms"。需读完整 PDF 或等待 v2 版本验证。置信度：中

与最强反驳的对话

"你只是把 MCTS 加了几个 tricks，本质还是在特定 Benchmark 上过拟合。"

——这个反驳部分成立。MCGS 的三个创新（图结构、渐进调度、多级停滞）单独看都不算革命性，但组合效果超过 60% 的整体提升，且在两个截然不同的领域（Kaggle ML 与数学优化）验证。组合创新 + 跨领域泛化比单点突破更能说明框架的通用价值。真正的检验是社区独立复现——GitHub 开源是一个积极信号。

7行业影响与展望

对 AutoML 行业

传统 AutoML（NAS、超参搜索）与 LLM Agent 的边界被进一步模糊。未来 6-12 个月，Kaggle 顶级方案很可能被 Agent + 少量人工引导 取代——这对数据科学家的职业角色是显著冲击。

对科研发现

跨领域泛化（打败 AlphaEvolve）意味着这套框架有潜力从 ML 工程扩展到 数学定理证明、蛋白设计、材料筛选 等长时段科研任务。GPT-5、Claude Sonnet 5、Gemini-3 之后的下一个前沿在这里。

对基础设施

Retrospective Memory 需要长期存储 (plan, outcome, feedback) 四元组，这将推动 Agent-native 向量库 与 过程记忆管理 成为新赛道。

对安全与治理

自进化 Agent 具备"越用越强"的属性，如何审计其自我修改路径、防止能力涌现失控，将成为治理层必须回答的问题。

8五点带走

  1. MLEvolve 用一半时间预算刷新 MLE-Bench SOTA（65.3%）——这不是渐进改进，而是效率跃迁。
  2. 三项核心创新：Progressive MCGS（图结构搜索）+ Retrospective Memory（可积累的经验记忆）+ Hierarchical Planning（规划-编码解耦）。
  3. 跨领域打败 AlphaEvolve：Kaggle ML + 数学算法优化双料 SOTA，展现真正的通用自进化能力。
  4. 值得警惕的对比不对等：与基线的骨干 LLM 代际存在差异，公平性需社区独立复现验证。
  5. 已开源：github.com/InternScience/MLEvolve ——这是判断其真实价值的最快路径。
