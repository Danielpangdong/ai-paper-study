DeepAgent：端到端"深度推理型 Agent"，让大模型自己发现工具、折叠记忆

来源：arXiv 2510.21618 · 中国人民大学 NLPIR · 精选自当日高影响力工作

⚡ 一句话总结（TL;DR）

DeepAgent 把"思考 → 找工具 → 调工具 → 记忆压缩"合并成同一个连续的推理过程，不再依赖 ReAct 那种硬编码工作流；并用一种叫 ToolPO 的强化学习方法，把奖励信号精细分配到"调用工具的那几个 token"，在 8 个 benchmark 上稳定超过基线。

🎯 它想解决什么问题

今天主流的 Agent 框架（ReAct、AutoGPT、function-calling pipeline）都有两个隐痛：

  • 流程是写死的：思考→行动→观察，循环固定，模型没有"全局自主权"，遇到没见过的任务就崩。
  • 长任务会"记忆爆炸"：几十步之后，上下文里堆满历史 observation，噪声大，错误会滚雪球。

再加一个训练层面的痛点：教模型用工具时，传统 RL 只在最后给一个粗颗粒奖励，模型搞不清到底是哪一次工具调用救了它、又是哪一次坑了它。

🧩 核心方法（三件套）

1. 端到端"深度推理"循环

自主思考
→
工具发现
→
动作执行
→
记忆折叠

四步不是固定 pipeline，而是模型在同一个 reasoning trace 里自己决定何时切换——这一点跟 OpenAI o 系、DeepSeek-R1 的"long CoT"思路一脉相承，但加了工具轴。

2. 自主记忆折叠（Autonomous Memory Folding）

把历史交互压缩进三块结构化记忆：

Episodic Memory
情景记忆

整段任务的关键事件

Working Memory
工作记忆

当前子目标 & 中间变量

Tool Memory
工具记忆

哪些 API 好用/坑

通俗理解：像人做长项目时会把厚厚的会议记录整理成"要点纪要 + 待办清单 + 踩坑笔记"，而不是每次都从头翻聊天记录。

3. ToolPO：把奖励精确打到"工具调用 token"上

Tool-call Advantage Attribution：不是给整条轨迹一个笼统的 reward，而是识别出"调用工具的那几个 token"，只对它们做优势归因。同时用 LLM 模拟的 API 训练，绕开真实 API 慢/贵/不稳定的问题。

📊 实验结果

在 8 个 benchmark 上稳定超越基线，覆盖两大类：

  • 通用工具使用：ToolBench、API-Bank、TMDB、Spotify、ToolHop
  • 下游应用：ALFWorld（家庭任务）、WebShop（网购）、GAIA（通用助手）、HLE（Humanity's Last Exam）

两种设定都拿下：labeled tool（明确告诉它有哪些工具）和 open-set retrieval（自己去一个大工具库里检索）——后者更接近真实场景。

⚖️ 最强反驳 & 局限

✅ 亮点

  • 把"工具"当一等公民塞进 CoT，方向对
  • 记忆折叠解决了长任务的现实痛点
  • ToolPO 的细粒度信用分配理论上更 sample-efficient

⚠️ 值得怀疑

  • LLM 模拟 API 有分布 gap：模拟器给的返回值太"干净"，真实 API 会有超时、格式漂移、429
  • ToolBench/API-Bank 早已被过拟合，成绩说明力打折
  • 没和 Anthropic MCP+Claude、OpenAI function-calling agent 这些商用系统做端到端对比
  • "自主记忆折叠"是否会丢关键低频信息，摘要没给消融

🛠 对你有什么用（实操层面）

  • 做 Agent 产品的人：可以借鉴"三层记忆 + 折叠"思路，别再无脑塞全历史到 context——现在 200K context 也扛不住 50 步真实交互。
  • 做 RL 训练的人：Tool-call 级别的 advantage attribution 是个可复用 trick，不一定非用 PPO 变体，DPO 上也能类比。
  • 做评测的人：ToolBench 分数别再当金标准，优先看 GAIA / HLE / open-set retrieval 场景。
  • 普通用户视角：这类研究成熟后，一年内你会看到 Claude/GPT 的 agent 在多步任务（比如"帮我订整个东京 7 天行程"）里错误率显著下降。

📌 术语快解（写给非科研背景）

  • Agent：能自己拆任务、调工具、执行多步的大模型系统，不是单轮问答。
  • ReAct：2022 年的经典范式，Reasoning + Acting 交替进行，是目前多数 agent 的默认写法。
  • RL / PPO：强化学习/近端策略优化，用"奖励"教模型什么行为好。
  • Advantage Attribution：给"每个动作"打一个"比平均好多少"的分，用来指导梯度更新。
  • Open-set tool retrieval：工具库有几千个，模型得自己搜出该用哪个，而不是给它一份短清单。
