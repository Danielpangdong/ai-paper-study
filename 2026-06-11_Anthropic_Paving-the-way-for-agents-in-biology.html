TL;DR · 一句话总结

当前最强的科研智能体（Claude Opus 4.7、GPT-5.5 等）在「从 NCBI Virus 检索病毒序列」这种基础任务上，准确率从 16.9% 到 91.3% 不等，且同一问题三次问会给出三组不同答案；瓶颈不在「推理」，而在数据库本身没有为智能体设计。作者发布 VirBench（120 道题、40 种病原体）作为基准，并以确定性检索层 gget virus 把所有模型拉到 90%+，GPT-5.5 达 99.7%。

  • 关键论点（高置信）：科学智能体的瓶颈正从「模型能力」迁移到「为智能体设计的基础设施」。
  • 关键证据（高置信）：在埃博拉疫情案例中，Sonnet 4 三次跑同一查询返回 106 / 15 / 5 条序列（期望 266），把疫情最近共同祖先时间（TMRCA）算错到 1922 年。
  • 关键解法（高置信）：把工作流中的「检索」剥离给确定性工具，让模型只负责创造性推理。
  • 开放问题（中置信）：当模型足够强，gget virus 这类「中间件」是否会被吞并？作者认为短期不会，因为可审计性、成本与可重复性仍重要。

🧬 背景：智能体走不通生物数据库

作者用一个比喻把问题点透：

「用 AI agent 跑生物数据库，像在一座古城里开车——街道是为行人设计的，再漂亮也没法跑现代车。软件世界本来就是为汽车（agent）铺的高速路：版本管理、API、包管理器。生物学没有。」

同样是「数据」，生物数据的现实是：

  • 分散：NCBI Virus 本质是 GenBank、RefSeq、INSDC、Pathoplexus 等多个底层资源的「门户」。
  • 过滤逻辑只活在 Web 界面里：浏览器一键的筛选，程序化几乎不可能复现。
  • 含义依赖语境：同一字段在不同库里语义不同，需要专家「默会知识」。
  • 错一个小细节就翻车：用错基因组版本、混淆 RefSeq/GenBank、漏掉 segment，下游结论全错。

这一节其实在重申 Karpathy 在「Software in the era of AI」演讲里的核心观点：「The code was the easiest part! Most of the work was in the browser, clicking things.」 作者把它平移到生物学：不止软件该为 agent 重写，生物数据库也该为 agent 重写。

示例查询（原文复刻）

「检索 NCBI 中 TaxID 3052462（Orthoebolavirus zairense, ZEBOV）的病毒序列：宿主为人；样本采集地为非洲；采集时间在 2014-01-01 至 2014-06-20 之间；最小长度 15,200 碱基；最大 1,900 个 N；排除实验室传代样本。」

对生物学专家来说这是 30 秒就能拍好的需求；对当前 agent 而言，它需要：拼接 REST / Datasets / E-utilities 三套 API、分页拉数据、本地再过滤、跨库 reconcile 标识符——任何一步漏掉，最终数据集都「看起来对，其实错」。

🛠 方法：把不确定性挪出 agent —— gget virus 确定性检索层

核心思路非常工程：不要让 LLM 自己拼 API，而是给它一把已经把 NCBI Virus 全部网页过滤语义复现好的 Python 函数。

gget virus 做了什么

  • 统一调度 REST、Datasets、E-utilities 三种底层 API。
  • 把「只活在 Web 界面里」的筛选逻辑，搬到本地确定性执行。
  • 处理大结果集分批拉取，避免「中途截断」。
  • 跨库（GenBank 等）补全元数据，再做过滤。
  • 输出标准化、可被人和机器读，附完整日志可审计。

这背后的设计哲学

「我们希望模型在『提假设、设计实验、推机制』时有创造力；但底层（标识符、schema、坐标系、元数据约定、检索路径）必须无聊地可靠。」

对应业界一个更宽的概念：context engine —— 围绕 agent 构建的可靠数据中间层。其他代表：ToolUniverse、Edison Robin、Biomni 等。

📈 实验结果：从「看天吃饭」到「逼近确定性」

VirBench 准确率：使用 vs 不使用 gget virus（数字基于 Anthropic 发布的柱状图近似读取）

注：原文柱状图未直接给出数字，本图据原图视觉位置估读，仅用于趋势展示。原文给出的明确数字为「6 个模型未加 gget virus 时准确率范围 16.9%–91.3%；加上后所有模型 > 90%；GPT-5.5 峰值 99.7%」。

关键发现

  • 模型选择不再决定一切：加了 gget virus 后，模型间差距大幅收敛——便宜模型也能跑出可靠结果。
  • 误差模式有规律：偏少 → 大结果集中途断流；偏多 → 过滤条件用错；尤其在 Influenza A、HIV-1、SARS-CoV-2 这类「记录爆炸」的病毒上最明显。
  • 当 filter ≥ 3-4 条时性能骤降：复杂语义检索是 agent 当前能力上限附近的任务。
  • GPT-5.5 自发使用工具：360 次跑里有一次，模型在没被显式提示的情况下自己调用了 gget virus —— 这也是该题唯一答对的运行。

💡 核心启示（写给从业者）

对 AI4Science 团队

  • 不要把 LLM 当「全栈科学家」用；把可形式化的环节抽出来做确定性工具。
  • 评估一个科研 agent，光看 benchmark 平均分不够，还要看「同题三次复测」的方差。
  • 「能跑」≠「能上线」：可审计性 + 可重复性是上下游协作的硬门槛。

对数据库 / SaaS 维护者

  • 把网页里的筛选语义对外暴露为 API；元数据字段做明确文档化。
  • 设计「机器优先」的输出：稳定的 schema、可追溯的日志、可复现的查询参数。
  • 承认「agent 是新的大型用户」，并把它列进 SLA。

对模型评测

  • VirBench 暴露了一类此前被忽视的失败模式：知识没错，但拿不到正确数据。
  • 建议把「带工具 / 不带工具」拆成两个独立分数发布。

最强反方观点（作者自己也提了）

「如果模型继续按当前曲线变强，agent 自己就能搞定 messy 的门户，gget virus 这类中间件不会被淘汰吗？」

作者承认有可能，但 push back：即便 agent 能跑，「每次都让 agent 临场重造一遍」在成本、延迟、可审计性、可信度上都不划算。这条反驳成立，但需要后续 1–2 年再观察。
