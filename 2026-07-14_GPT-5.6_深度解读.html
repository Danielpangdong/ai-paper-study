四个真正值得关注的技术变化

1. Programmatic Tool Calling（可编程工具调用）

过去的 tool use：模型每一次调用工具都要把"工具的返回值"喂回上下文，再让模型决定下一步。token 消耗和延迟被工具轮次拖垮。

新做法：模型可以在 Response API 内直接写并运行一段 JS 程序，由这段程序去编排多次工具调用、过滤中间结果，只把"值得看的部分"塞回上下文。

官方对比：Clio 的多步文档分析任务，prompt tokens 直接降 38%，质量不变。PlayCo 的 Unity 场景构建，总 token 降 63.5%，模型轮数降 50.1%。
通俗理解：过去像"每一步都请示老板"，现在给了老板一支笔和一张便签，让他先自己算，只回报结论。

2. Multi-Agent / ultra 档

ultra 档默认起 4 个子智能体并行工作，最后合并结果；在 API 里叫 multi-agent beta，开发者可以自定义子智能体数量与拓扑。

官方 BrowseComp 数据：单 agent → 4 agent → 16 agent 曲线整体"向左上移动"，即在同等或更短时间内拿到更高分。

但要冷静： 多智能体并行 = token 消耗成倍。ultra 挂 16 agent 时成本几乎不再是"廉价"。这是把云计算里"横向扩展 vs 纵向扩展"的老问题搬进推理层——用钱买时间。

3. 显式 Prompt Cache Breakpoints

Anthropic 早在 Claude 上做过显式缓存断点，OpenAI 现在跟上：开发者可以自己声明"这一段是稳定前缀，缓存它"，命中率与折扣变得更可控。

  • 缓存最短保留时间：30 分钟
  • 缓存写入：按原价的 1.25× 计费
  • 缓存命中：按 10% 输入价（即 90% 折扣）计费

4. max 推理档 & 图像 detail:original

max：比 xhigh 更极端的推理档，给模型更多"思考 token 预算"去反复自检、探索、修正。

detail: original：图像不再默认被下采样，视觉任务能保留原始分辨率。这对 UI 审查、代码截图、图表分析类场景是刚需。

为什么 "$/token" 不再是好指标？

agentic 模型自己决定推理 token 数量：同一任务，Sol 在 max 档可能烧 10 万 token，Fable 5 只烧 3 万 token，也可能反过来。所以真正的成本对比只能看"任务完成成本"。

OpenAI 的隐藏叙事其实是："我们更贵的模型，因为更省 token，反而更便宜"——这套逻辑站得住的前提是：任务结果真的对得起价格。

建议决策方式：
  • 拿你的真实任务跑 A/B（Sol vs Sonnet 5 vs Fable 5）
  • 记录"任务成功率 × 总花费"，而不是"每百万 token 单价"
  • 把 Programmatic Tool Calling 打开再测——那才是 OpenAI 的真实杀器
