TL一句话结论

这篇论文指出：LLM 强化学习里所有人都在优化"训练引擎里的策略 π"，但实际部署跑推理的是另一套引擎里的策略 μ——由于精度、后端、量化差异，两者就算参数同步、给同一条轨迹算出的概率也不一样。所以哪怕训练侧看似进步，推理侧完全可能没提升甚至恶化。作者把"推理策略单调提升"（MIPI）作为真正的优化目标，并给出两步算法 MIPU：先做 sampler-referenced 更新，再用推理侧的 gap 代理筛掉"训练涨、推理没涨"的更新。 在 FP8 量化推理（高不匹配场景）下，Qwen3-1.7B/4B 的数学推理平均分同时提升且训练不再崩溃。

1问题：什么是"训练—推理不匹配"？

现代 LLM RL 把生成和梯度计算分成两条工程链路：

推理引擎 μ
vLLM / SGLang
为吞吐做了 FP8 量化、KV-cache、连续批处理
→ 负责 rollout（采样轨迹）
→
参数同步
每个 step 把权重从训练侧刷到推理侧
同一份参数
→
训练引擎 π
FSDP / Megatron
BF16/FP32 高精度反传
→ 计算 log-prob 和梯度

问题在于：参数相同 ≠ 概率相同。同一条轨迹 y，两个引擎给出的对数似然会不同。

πk(y|x)  ≠  μk(y|x)   （即使参数同步）

这是一种永远存在的 off-policyness：数据是 μ 采的，但训练算法把它当作 π 采的来更新，会持续"投毒"训练。FP8 量化让这个 gap 尤其大。

2核心洞察：过去的工作都在优化错的对象

过去一年主流的解决方案有三类：

修 off-policyness 的 tricks

  • MIS / TIS：修正重要性采样比
  • 样本过滤：扔掉不稳定的 rollout
  • LR-decay：降低学习率抑制爆炸
  • 系统层：缩小两个引擎的实现差异

它们的共同盲区

都在"稳住训练策略 π"，但假设 π 涨 = μ 涨——这是海市蜃楼。作者形式化地指出：

J(πk+1) − J(πk) ≥ 0  ⟹̸  J(μk+1) − J(μk) ≥ 0
关键设问：真正该问的不是"这次更新让训练策略更好了吗？"，而是——
"参数同步过去之后，推理策略真的变好了吗？"

3MIPI：新的优化目标

作者提出把推理策略的单调提升作为真正目标：

max   J(μk+1) − J(μk)

关键的数学动作是把它拆成三段可解释项：

J(μk+1) − J(μk)  =  ① [J(μk+1) − J(πk+1)]  +  ② [J(πk+1) − J(πk)]  +  ③ [J(πk) − J(μk)]

② + ③ = 训练侧更新

两项望远镜求和后等于 J(πk+1) − J(μk)——即"用 sampler μk 作参考"的更新，而不是用旧的 πk。
→ 对应 Step 1：Sampler-Referenced Policy Update。

① = 同步后的推理 gap

训练更新完，把参数刷到推理侧，检查 μk+1 相对 πk+1 有没有被"打回原形"。
→ 对应 Step 2：Inference-Gap-Aware Acceptance。

4MIPU 算法：两步实现

Step 1 — Sampler-Referenced Policy Update

关键在于把重要性权重因式分解为"预更新失配 wk"和"当前更新 r(θ)"两部分，只裁 r(θ)，但对 wk 做截断（TIS）控制方差：

ρ(θ) = wk · r(θ),   w̄k = min(wk, wmax=2)

作者比较了 IS / MIS / TIS 三种变体，TIS 在稳定性 vs. 性能上取得最佳权衡。

Step 2 — Inference-Gap-Aware Update Acceptance

把参数同步过去后，在验证集上估计"post-update 推理 gap"的代理量 T̂post。逻辑很干脆：

训练侧更新 πk → πk+1
→
同步权重
μk+1 ← πk+1
→
估计 T̂post
≥ −c → 接受 < −c → 回滚

只有"训练侧涨、同步后推理侧也真的涨"的更新才被保留。这样保证的是真部署策略的单调提升。

7意义与可迁移的启示

可迁移的一句话原则：当训练系统和部署系统不是"同一系统"时——不管差异来自量化、编译、还是引擎实现——优化目标必须锚在部署系统上，而不是训练系统上。这一原则在推荐系统、量化推断、蒸馏部署里都是通用的。

对工业界

直接可用：如果你的 RLHF pipeline 是 vLLM rollout + FSDP 训练 + FP8 量化推理，MIPU 的两步框架是 drop-in 改动，代码复杂度低。

对研究界

提供了一个新范式："训练-推理协同优化"作为独立研究方向。后续可能延伸到：更廉价的 gap proxy、on-the-fly gap 估计、多引擎联合优化。
