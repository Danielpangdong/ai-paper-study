HiViG：给电脑使用智能体配一个“看得见屏幕、记得住进度”的执行前审稿人

今日精选论文：A History-Aware Visually Grounded Critic for Computer Use Agents。它研究的不是让 AI 再聪明一点，而是让 AI 在点击、输入、删除、发送之前，先被一个懂历史、懂屏幕坐标的多模态审稿人拦一下。

arXiv:2606.11078 Computer Use Agents GUI Automation Multimodal Critic UNC / Capital One / UT Austin

一句话讲透论文

HiViG 本质上是在给 AI 办公助手配一个“执行前质检员”：它先翻看任务进度本，再盯着屏幕确认鼠标真的点在正确位置，最后才允许主智能体动手。

今天的电脑使用智能体已经能打开网页、填写表格、操作手机 App 或办公软件。但它们经常犯两类很像真人新手的错误：第一，做着做着忘了前面已经完成了什么，于是在同一个地方反复绕圈；第二，它说自己要点“提交”，实际坐标却点到了旁边的“删除”。

HiViG 的关键不是再训练一个万能大模型，而是在测试时插入一个小型多模态 critic。它不替主智能体完成任务，而是在每一步执行前做两件事：更新宏观行动历史，并对当前截图里的原始坐标做视觉校验。

为什么今天选它？

过去两年，行业一直在说“Agent 会替你操作电脑”。但真正落地时，问题往往不在模型会不会写计划，而在它能不能可靠地做完很多细小、连续、不可逆的界面动作。HiViG 把这个问题抓得很准：执行前审查比事后补救更接近真实生产环境。

把历史压缩和视觉坐标校验合成一个测试时干预框架。
产业落地
强
直接面向网页、移动端、桌面办公软件等真实 GUI 工作流。
长期价值
清晰
可靠 Agent 的关键可能不是更大模型，而是可审查、可纠错的执行回路。

如果说 RAG 是给语言模型加“查资料能力”，HiViG 更像给电脑使用智能体加“上岗前复核能力”。这对企业软件、自动报表、客服后台、跨系统录入、低代码操作都有现实意义，因为很多 GUI 动作不是错了再撤销就行，发送邮件、删除文件、提交表单都可能不可逆。

核心贡献拆解

贡献它提出了什么解决什么问题为什么更好
宏观行动历史把一串细碎点击和输入压缩成“已经完成了哪些阶段”的进度记录。避免智能体只看最近几步，忘记全局目标，陷入重复操作。像项目经理的任务看板，让下一步决策知道当前真正进度。
视觉落地批评在当前截图上检查原始执行坐标，并指出动作会不会落在错误 UI 元素上。解决“语言意图正确，但鼠标点错地方”的 GUI 自动化硬伤。不只听智能体自称要做什么，还看屏幕上实际会发生什么。
执行前干预critic 在动作改变环境之前给出自然语言反馈，让策略模型重新修正。减少事后回滚，尤其适合删除、发送、提交等不可逆动作。更像真实公司的审批流：先审，再执行。
跨平台评测在 WebArenaLitev2、AndroidLab、WindowsAgentArena 上测试。避免只在单一网页或单一手机任务上证明有效。证明方法依赖截图和像素理解，不依赖某个平台专属 DOM 或辅助功能树。

工作原理：像“实习生 + 带教老师”的组合

可以把主智能体想象成一个会操作电脑的实习生。实习生每一步都会说：“我准备点这里。”HiViG 像带教老师，它不抢键盘，而是先问三件事：

第一，前面已经完成了什么？第二，当前截图里，准备点击的位置到底是不是目标？第三，如果这个动作有问题，应该怎么改？

最重要的直觉：HiViG 不是让智能体“想更多”，而是让它“别在看错屏幕、忘记进度时动手”。这比单纯加长上下文或多采样几个动作更接近真实自动化系统的安全需求。

实验结果解读：不是满分，但方向很关键

论文在三个 GUI 环境里评估：网页 WebArenaLitev2、手机 AndroidLab、桌面 WindowsAgentArena。结果最值得读的地方是：HiViG 对开源模型 Qwen3-VL-32B-Thinking 和闭源 Gemini-3-Flash 都有提升，说明它不是只为某一个模型定制的补丁。

它和旧方法到底有什么不同？

路线过去常见做法HiViG 的做法潜在收益
直接让主模型执行模型看截图，生成点击或输入动作，马上执行。先把动作交给 critic 做执行前复核。降低不可逆 GUI 动作的风险。
标量奖励模型给候选动作打分，选分数最高的。用自然语言说明坐标、历史和界面状态哪里不对。当所有候选都不好时，不只告诉你“低分”，还能告诉你怎么改。
普通 verbal critic主要根据动作描述和短上下文批评。强制检查截图中的真实坐标，并维护宏观历史。减少“语言听起来对，但屏幕上实际错”的问题。
平台专用方法依赖 DOM、accessibility tree 或特定系统接口。主要依赖截图和像素级视觉理解。更容易跨网页、手机、桌面泛化。

局限性与问题

它还远远不是可靠办公 Agent。即使用上 HiViG，Gemini-3-Flash 平均成功率也只有 50.4，Qwen3-VL-32B 为 38.3。生产环境不能把它当成自动放行系统。
算力成本不低。论文使用 Qwen3-VL-8B-Thinking 训练 critic，训练和评测都涉及 8 张 H100 80GB；长流程 GUI 评测本身也很贵。
问题为什么重要需要关注什么
细粒度视觉差异论文指出 critic 可能分不清非常细微的颜色或视觉选项。真实办公里格式、颜色、单元格范围都可能决定成败。
历史摘要也会错如果 critic 把“隐藏配置页”误记成“已删除闹钟”，后续计划会被污染。需要可回放的状态证据，而不只是压缩摘要。
单次实验限制论文说明由于长流程任务成本高，实验结果来自 single run。后续需要更多重复实验和企业场景复现。
安全边界执行前审查减少错误，但不等于权限、审计、审批、回滚都解决了。高风险动作仍需要权限分级和人类确认。

产业影响分析

谁会受益

企业 RPA、浏览器 Agent、办公自动化、客服后台、测试自动化、移动端操作助手、远程运维工具。

谁会被冲击

只依赖提示词让模型直接点屏幕的薄封装产品，会越来越难证明可靠性。

竞争焦点

从“能不能操作界面”，转向“能不能证明每一步操作被审查、可追踪、可纠错”。

对产品经理来说，这篇论文的启发很直接：Agent 产品不能只设计聊天框，还要设计执行链路。每一步行动都应该有候选动作、屏幕证据、历史进度、风险判断和失败恢复。未来企业 Agent 的护城河，很可能不只是模型能力，而是这一整套可验证执行系统。

如果把它放进未来五年

五年后回看，HiViG 这个具体模型未必还会被直接使用，但它代表的设计方向大概率会留下来：电脑使用智能体需要“行动前的多模态质检层”。

这类似自动驾驶不能只靠一个端到端模型直接控制方向盘，还需要感知、预测、规划、监控、接管机制。GUI Agent 也是一样。真正能进企业的系统，必须让每一次点击和提交都能被解释、被审查、被记录。
