一句话讲透

当你说“让 agent 删除文件前必须二次确认”时，Harness Handbook 试图先把这项行为涉及的 prompt、权限、状态、工具包装与执行分支找全，再让人或 coding agent 修改；它不替你证明改动正确，但降低了“只改到显眼那一处”的风险。

问题背景

旧方法卡在哪里

文件树、关键词搜索、代码向量库和长上下文能让代码“更容易看见”，却仍要求开发者从散落的函数、模块与状态流中自行拼出“某个行为由哪些地方共同决定”。

为什么 agent 特别棘手

一个用户可见行为往往跨 prompt、工具 schema、权限策略、状态管理、sandbox 与异常回退。改动需求按“行为”描述，仓库却按“文件”组织，这就是论文称的 behavior localization 缺口。

核心贡献

  1. 定义行为定位问题：先找全实现某项行为的代码位置，再制定编辑计划。
  2. Harness Handbook 表示：以 L1 系统概览、L2 行为阶段、L3 源码证据的层级组织代码，并补充跨阶段 state register。
  3. BGPD 工作流：从行为描述逐级缩小范围，再对照当前源码验证候选位置。
  4. 同步机制：每次非空 diff 后重解析受影响部分；无法验证的条目冻结而非猜测。
  5. 受控比较：在 Codex 与 Terminus-2 上各用 30 个行为驱动改动请求，对比有无 handbook 的同一 planner。

技术路线可视化重构

工作原理

把大型 agent harness 想成一座机场。文件树像按部门摆放的柜子：值机、安检、行李、登机各放一处；但“乘客能否登机”这件事实际跨越多个部门。Handbook 像一张按“旅客行为”编排的运行手册：先看全程，再看某环节，最后指向具体柜台与规则。

类比边界：手册不是机场本身，也不会自动保证所有柜台规则正确。论文的 L3 locator 只有在能在当前代码中重新验证时才可用于定位；这降低过期说明误导的风险，却不等同于测试通过、没有安全漏洞或生产可靠。

实验结果怎么读

论文比较的是改动前的定位与计划质量，不是最终 patch 的测试通过率。两组都用 DeepSeek-V4-Pro planner、相同请求、快照、工具权限和 decoding；区别仅是 planner 是否先读取 handbook。三位 judge 是 GPT-5.5、Opus 4.8、DeepSeek-V4-Pro（论文 §4.1）。

失败案例与局限性

  • 只测两个 harness、各 30 个请求。Codex 很大（2,267 files、34,363 internal-function nodes），但样本仍有限；通用性待第三方复现。
  • 目标是 plan，不是修复结果。没有在本文实验中报告修复后测试通过率、回归率、安全事件或线上成本。
  • 评估依赖模型 judge 与模型参考计划。虽有三位独立 judge、两份强模型参考计划，但不是人类审稿式 ground truth。
  • 静态事实有盲区。未解析、动态调用或过期 locator 被记录/冻结；这比臆测更安全，却可能降低覆盖。
  • 自家方法/自选请求风险。论文采用同设置对照，但请求构造、handbook 质量和实际仓库的可解析度仍可能影响收益。

产业影响

最先受益：维护大型 agent harness、内部开发平台、合规/权限链复杂的企业团队。价值不只是“省 token”，而是把 prompt、schema、权限和执行层的跨文件依赖变成可审查证据。

受冲击的做法：仅靠关键词检索、repo map 或把整个仓库塞进长上下文的工作流。它们不会消失，但可成为 handbook 的事实输入或 fallback，而非唯一导航。

落地节奏：短期可做为 read-only 规划辅助；中期接入 PR 影响分析与权限审计；真正自动执行需要把 locator 验证、测试、审批和差异审查串起来。成本变化：论文仅在规划 token 上报告 −12.7% / −8.6%，不能直接外推为总开发成本下降同等比例。

对产品/创业/投资的启示

事实

在论文所设对照中，行为导向的源码地图使计划偏好率上升、平均 planner token 下降，且在两种粒度上对两份参考计划的 F1/Recall/Precision 均更高（Table 1、Figure 3）。

推演（有条件）

AgentOps 的差异化可能从“更强模型”转向“可验证的 harness 解释层”：变更影响图、政策路径审计、状态读写账本和 diff 后同步。失效条件：目标代码高度动态、定位不能及时复核、团队不愿维护结构化地图，或测试/审批链仍不可用。

不要把它当成自动改代码的绿灯。更合理的产品形态是：对每个建议改动同时交付“行为链、涉及文件/符号、证据片段、测试建议、风险分支”；人类仍决定是否执行。

三句话复盘与 3 道理解题

  1. Harness Handbook 的核心不是摘要代码，而是让“行为 → 实现位置”的映射可导航、可复核。
  2. 论文在两套开源 harness 的受控规划实验里看到更高偏好率与更低 token，但未证明最终 patch 或生产可靠性。
  3. 最值得落地的是把它放在编辑之前：先找全跨模块影响，再测试、评审、执行。
