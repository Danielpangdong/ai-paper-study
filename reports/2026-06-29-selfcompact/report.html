7 模型

跨模型验证

覆盖 4 个 Qwen 数学模型和 3 个部署型搜索 Agent。

1. 为什么今天选它？

因为 Agent 的真正瓶颈，正在从“会不会调用工具”转向“能不能长期保持清醒”。

今天的 AI Agent 做复杂任务时，会不断产生推理、搜索结果、代码执行输出、错误尝试和中间计划。问题是：这些内容会越堆越多。就像一个学生解数学题，草稿纸上既有正确线索，也有被划掉的错误路线。如果他从头到尾都盯着整张乱纸看，反而更容易被旧错误带偏。

工业系统已经在做“压缩上下文”：Claude、Cursor、LangChain 等都在用不同方式减少长会话成本。但很多方法像闹钟：到某个 token 阈值就压缩。SelfCompact 的价值在于把问题改成：能不能让模型自己判断，现在是不是适合整理笔记？

这件事长期重要，因为未来的 Agent 不是只回答一次问题，而是连续工作几十分钟、几小时甚至几天。长期任务需要的不只是更大上下文，而是更好的上下文卫生。

2. 核心贡献拆解

提出了什么

SelfCompact：一个不训练模型、不改参数的推理时脚手架。它给模型一个“压缩工具”，再给一段判断准则，让模型决定何时调用。

解决了什么

解决固定时间压缩的误伤问题。固定阈值可能在模型正推到一半时把关键线索总结丢。

为什么更好

它把压缩放在“任务边界”附近，例如一个子问题刚解决、搜索线索刚确认、答案开始收敛的时候。

3. 工作原理：像整理侦探案板

把 Agent 想成侦探。墙上贴满照片、线索、错误嫌疑人、地图和便利贴。如果每 30 分钟让助手随机把墙上的内容整理成一页纸，可能刚好把最关键的线索收走。SelfCompact 更像让侦探自己说：“这个嫌疑人已经排除，这条线索已验证，现在可以整理一次。”

论文中的关键设计很朴素：模型输出一个类似 <summarize> 的信号；脚手架把此前轨迹总结成较短的自然语言摘要；随后模型从这个摘要继续工作。不同点在于：它不是单纯相信模型“想压缩就压缩”，而是用 rubric 约束何时该压缩、何时不该压缩。

4. 与旧方法对比

方法像什么优点风险SelfCompact 的差异
不压缩草稿纸永不整理不会丢信息成本越来越高，旧错误污染后续推理把旧噪声压缩掉
固定阈值压缩闹钟一响就整理简单，容易工程化可能在关键推理中间打断按任务状态而非 token 数触发
只保留最近几轮只看最后几页笔记便宜可能忘掉早期关键线索保留已验证事实，而不是只按时间保留
SelfCompact完成一个小目标后整理案板减少噪声，保留结构化进展依赖模型遵守 rubric，摘要仍可能出错训练免费，能叠加到现有 Agent

5. 实验结果怎么读

论文做了两类测试：一类是竞赛数学，考验长推理；一类是 Agent 搜索，考验多轮工具调用。关键不是“分数涨了”，而是涨分同时还省钱。

6. 关键术语解释

Context Window 上下文窗口专业：模型一次推理可读取的 token 上限。白话：AI 当前桌面能摊开的纸张大小。
Context Rot 上下文腐烂专业：长上下文中的旧错误、过时信息影响后续输出。白话：草稿纸越乱，越容易被之前的错路带偏。
Compaction 压缩专业：把历史轨迹总结成较短表示后继续推理。白话：把一堆便利贴整理成一页清单。
Rubric 评分准则专业：指导模型何时触发或抑制压缩的规则。白话：告诉 AI 什么情况下该整理桌面，什么情况下别打断自己。
KV Cache专业：推理中缓存过的注意力键值，减少重复计算。白话：AI 已经看过的内容做了速记，下次不用全部重读。
Agentic Search专业：模型通过多轮搜索、工具调用和判断来回答问题。白话：AI 像研究助理一样边查资料边改答案。

7. 局限性与风险

不要把 SelfCompact 理解成“完美记忆”。 它仍然可能总结错、漏掉关键细节，或者在某些模型上不稳定。
问题具体含义落地建议
摘要失真压缩后的自然语言摘要可能丢掉边界条件、数值、引用来源关键状态应结构化保存，例如任务 ID、证据链接、待办列表
模型能力依赖论文主要测开放权重模型，顶级闭源模型可能已有更强自省能力在自家模型和任务上做 A/B 测试，不要直接照搬阈值
安全与审计压缩会改变可见历史，可能影响责任追踪保留原始轨迹日志，摘要只作为工作上下文
复杂工程工具调用、缓存、摘要、回放都要稳定配合先在长搜索、长代码任务中小范围试点

8. 产业影响分析

谁会受益？ 最直接受益的是编码 Agent、深度研究 Agent、企业流程自动化 Agent 和需要长会话的客服/运营系统。它们都面临一个共同问题：用户越依赖 Agent，任务越长，旧上下文越贵也越危险。

谁会被冲击？ 只靠“更大上下文窗口”作为卖点的系统会被重新定价。未来竞争不只是上下文有多大，而是能不能把上下文变成可管理、可审计、可压缩的工作记忆。

对产品经理的启发： Agent 产品要有“工作状态层”。聊天记录不是状态管理。真正可用的长期 Agent，需要把目标、证据、决策、风险、用户偏好分层存储，压缩只是其中一环。

对投资人的启发： 这类论文指向一个正在形成的基础设施市场：上下文工程、Agent 记忆、轨迹压缩、状态审计、成本优化。它们会像向量数据库和 RAG 一样，成为应用层 AI 公司的底层刚需。
