令牌内省：
授权此刻还算数吗？

Token Introspection · RFC 7662

当 AI 助手带着令牌来调用日历、仓库或客服系统时，资源服务器可以不只看“这张通行证长什么样”，还可以向授权服务器问一句：它现在仍有效、能进这扇门吗？这次在线核验就叫令牌内省。

一句话：问发证方令牌当前状态核心角色：资源服务器 ↔ 授权服务器不是“读懂令牌”的同义词
知识地图位置：最小权限 → OAuth Scopes → Access Token → Refresh Token → PKCE → Token Revocation → DPoP → Token Introspection（今日） → Authorization Server Metadata / mTLS-bound Tokens。
承接 DPoP：DPoP 回答“谁在出示令牌”；令牌内省回答“令牌现在是否仍有效、携带哪些授权上下文”。

01 · Why first

为什么重要：令牌会在发出以后改变状态

AI 代理常代表人调用外部工具。即使它手中的是一枚未过期的 Access Token，用户也可能已经撤销授权、管理员也可能已停用账号、权限范围也可能已收缩。若资源服务器只依赖自己手里的旧判断，就可能把一张已失效的通行证继续放行。

事实 · 标准说的是什么RFC 7662 定义了一种协议：受保护资源向授权服务器查询某枚 OAuth 令牌的元数据，例如是否 active、范围 scope、客户端与授权上下文；这可用于结构化或非结构化令牌。
推断 · 对 AI 工具调用意味着什么当“撤销后尽快生效”比“每次请求少一次网络往返”更重要时，在线状态查询会是系统设计里的一个候选环节，而不是 AI 模型本身的一项能力。

没有它会怎样？

状态滞后撤销已经发生，但离线校验仍只看见未过期的签名与时间。
不透明令牌无从自验令牌若只是随机编号，资源服务器没有授权服务器的数据库就无法知道含义。
策略难以统一不同工具各自猜测令牌状态，易出现允许与拒绝不一致。
02 · One analogy throughout

贯穿类比：进园区前给“发证中心”打电话

把 AI 助手想成来园区取件的司机，Access Token 是它递出的电子通行证，资源服务器是门岗，授权服务器是发证中心。门岗有两种做法：一是查看证件上的防伪与截止日期；二是在关键时刻打电话给发证中心，询问“编号 7K9 现在仍放行 3 号库吗？”后者就是令牌内省。

教学视觉 1 · 类比中的“问一问”阅读顺序：司机出示通行证 → 门岗查询 → 发证中心返回现在状态 → 门岗放行或拒绝。
图注与依据：类比对应 RFC 7662 的“受保护资源查询授权服务器”。图中“现在状态”可包含有效性与授权上下文，而非只检查格式。
看图结论：门岗不是向司机要“更多令牌”，而是用自己的凭据向发证中心核实同一枚令牌。
类比失真处现实里的资源服务器不会拨电话、也不应把令牌随意泄露给任何人；这是经 TLS 保护、且调用者必须被授权的 HTTP 端点。发证中心返回 active:false 也不等同于“世界上不存在这枚令牌”——标准刻意减少无效令牌的额外信息，以降低探测风险。
03 · Input → process → output

一图看懂：把“令牌字符串”变成一次授权决定

教学视觉 2 · 在线核验的输入、步骤与输出阅读顺序：左到右；蓝色是请求，绿色是响应，最后一格是本地策略决定。
图注与依据：RFC 7662 规定内省请求使用 POST，返回 JSON；active 是响应中唯一必需的顶层成员，其余字段依实现与授权决定需要而定。
看图结论：内省给的是“当前授权事实的输入”，最终是否放行仍要由资源服务器按自己的业务策略决定。
04 · Mechanism

工作原理：六步，不把“在线查询”误说成“万能验证”

1资源请求到达

AI 工具调用把 Access Token 交给资源服务器。

2先识别触发条件

系统可对所有请求、敏感操作或缓存到期后发起查询；这是架构选择。

3资源服务器认证自身

内省端点不能开放给任意人，否则会成为令牌扫描器。RFC 7662 要求某种访问授权。

4经 TLS 发送 POST

提交 token，可附 token_type_hint；提示可被忽略，不能替代真正查找。

5授权服务器计算当前状态

“active”的具体定义由授权服务器决定，常涉及签发方、时间窗、撤销与适用资源。

6返回事实，资源服务器执行策略

active:true 仍不自动等于“允许任何操作”；还要检查范围、受众与业务条件。

一个很容易漏掉的协议细节一份格式正确、权限也足以查询的请求，若令牌无效或不允许被查询，规范要求以 {"active":false} 回答，而不是把它当成普通协议错误。这有助于少泄露内部状态。
05 · Vocabulary

关键术语：专业解释、白话解释、易混淆点

Token Introspection（令牌内省）专业：受保护资源通过内省端点向授权服务器查询 OAuth 令牌元数据的协议。
白话：门岗向发证中心查证。
易混淆：不是客户端自己“看看令牌内容”。
Introspection Endpoint（内省端点）专业：接收令牌参数并返回 JSON 元数据的 OAuth 端点。
白话：发证中心的查证窗口。
易混淆：它不是发新令牌的 /token 端点。
active专业：响应里必需的布尔字段，表示令牌是否处于授权服务器定义的有效状态。
白话：“此刻可用吗？”
易混淆：true 不是“可访问所有 API”。
Resource Server（资源服务器）专业：承载受保护 API、执行访问控制的服务。
白话：真正掌管日历、文件或订单的门岗。
易混淆：通常是它而非 AI 客户端调用内省。
06 · A sourced product use

一个有来源的真实应用：Okta 的远程验证路径

Okta 的开发者文档把验证访问令牌分为本地与远程两路：远程方式使用 Token Introspection Endpoint。该文档明确提示，网络请求会更慢；但当需要确认令牌没有被撤销时，它提供了这个选择。另一份 Okta 指南展示了对 /introspect 的 POST 请求，以及包含 active、scope、aud 等字段的响应。

从产品文档到设计判断（推断）这不是“JWT 一律在线查”的结论，而是一个取舍样本：高频、低风险读取可能偏向本地校验或受控缓存；撤销敏感的关键动作可更接近授权服务器的当前状态。具体频率与故障策略必须由系统风险模型决定。
07 · Neighbors, not synonyms

相近概念对比：它解决的不是同一个问题

教学视觉 3 · 四个问题，四种机制阅读顺序：先读最左列“问的问题”，再看各机制的答案；同一系统可以组合使用它们。
图注与依据：RFC 7662（内省）、RFC 7009（撤销）与 RFC 9449（DPoP）是不同协议；RFC 9700 将 sender-constrained token 推荐为降低泄露重放风险的机制。
看图结论：撤销负责“改状态”，内省负责“读状态”，DPoP 负责“证明谁在出示”；本地 JWT 校验负责“在本地核对可验证的声明”。
概念主要信息源强项典型盲区
令牌内省授权服务器当前状态可观察撤销与不透明令牌网络依赖、缓存会带来陈旧窗口
JWT 本地校验令牌中的签名与声明快、无需每次联网未必立即得知撤销
令牌撤销授权服务器状态变更主动使授权失效不替资源服务器完成每次判断
DPoP请求签名与绑定关系降低复制令牌的重放价值令牌被撤销或过期仍须另行处理
08 · Three traps

至少三个误区

误区 1：active:true 就能执行一切纠正：它只表示授权服务器认为令牌有效；资源服务器仍要看目标 API、范围、受众和自身业务规则。
误区 2：内省就是解码 JWT纠正：JWT 可以本地校验；内省是网络协议，甚至对随机、不透明的令牌也能工作。
误区 3：只要有撤销端点就不用内省纠正：撤销改变授权服务器状态；资源服务器要何时、怎样看到变化，是另一项设计。
误区 4：任何客户端都能拿令牌去查纠正：内省端点必须要求调用者有授权，否则会泄露令牌状态并被用于扫描。
误区 5：缓存越久越省事纠正：缓存减少延迟，但可能让撤销后的旧结果暂时继续被使用；规范要求权衡性能与安全。
误区 6：它能替代 DPoP纠正：内省不证明来访者持有哪把私钥；它与 sender constraint 回答的是不同问题。
09 · Limits & risk

限制、风险与适用边界

适合考虑的场景

  • 令牌为不透明值，资源服务器无法独立读取授权信息。
  • 撤销、账号停用或即时策略变化需要较快反映到关键 API。
  • 多个资源服务器希望以授权服务器为授权状态的中心来源。

需要谨慎的场景

  • 极低延迟或高吞吐路径：每次远程查询可能成为瓶颈与单点依赖。
  • 授权服务器故障时：必须事先定义超时、重试、缓存与拒绝/降级策略。
  • 敏感日志与可观测性：请求体含令牌，不能把它记进普通日志或埋点。
安全底线使用 TLS；对内省调用者做认证与授权；限制返回给不活跃令牌的额外信息；把令牌当秘密处理；慎重设计缓存时间。RFC 7662 明确要求保护端点、要求某种访问授权，并提醒缓存安全信息存在性能—安全权衡。
10 · Retain it

三句话总结与三道理解题

  1. 令牌内省是资源服务器向授权服务器查询令牌当前状态与上下文的协议。
  2. 它特别适合需要观察撤销、不透明令牌或统一授权状态的情形，但会引入网络依赖。
  3. 它不等于 JWT 解码、令牌撤销或 DPoP；四者可组合，各自解决不同的问题。

Q1：为什么 active:true 还不能直接放行“删除所有文件”？

答：令牌有效不等于该操作被允许。资源服务器仍要检查 scope、audience、目标资源和自己的业务授权规则。

Q2：用户刚撤销授权，为什么本地 JWT 校验可能还通过？

答：它只校验令牌携带的签名和时间等可验证信息；除非系统取得更新状态，否则未必立即知道撤销。内省可向授权服务器询问当前状态。

Q3：DPoP 和内省能否同时使用？

答：可以。DPoP 可验证出示者持有绑定私钥；内省可查询授权服务器所知的当前令牌状态。是否组合取决于威胁模型与部署支持。
11 · Curriculum delta

知识地图增量

继承最小权限告诉我们“权限应当收窄”；Scopes 表达范围；Access / Refresh Token 让调用得以持续；PKCE 和 DPoP 分别降低代码截获与令牌重放的风险；Token Revocation 改变授权状态。
今日新增资源服务器不必只相信令牌的静态外观：可以经受保护的内省端点，向授权服务器查询当前授权事实。
被修正的直觉“令牌检查”不是单一动作。验签、问在线状态、撤销、证明持钥分别回答不同问题；不能互相替代。
下一步候选① OAuth Authorization Server Metadata：资源服务器怎样发现内省端点；② mTLS-bound Tokens：另一条 sender-constraining 路径；③ RFC 9701：把内省响应以 JWT 形式返回的扩展。
