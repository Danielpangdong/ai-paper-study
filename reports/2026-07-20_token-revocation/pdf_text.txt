令牌撤销
Token Revocation

当你卸载一个能读日历、云盘或邮箱的 AI 助手时，为什么不能只把 App 删
掉？这堂课讲清“收回授权”的协议动作，以及它不能替你做到的事。

  核心一句话：令牌撤销是授权服务器收回某个令牌及其相关授权的机制；但旧 Access Token 能否在所有服务
  上立刻失效，取决于系统怎样验证令牌。

04 · 工作原理


六步看令牌怎样从“还能用”变成“不能再用”

  1 决定收回授权
    用户点击“移除某应用访问权限”，客户端退出登录，或安全系统发现风险。先分清目标：只是结束本机会话，
    还是让服务器收回授权？只有后者才是令牌撤销问题。




  2 向可信端点提交撤销请求
    客户端把待撤销的 token 放入 HTTPS 的 POST 请求体； token_type_hint 是可选的查找提示，不是令
    牌类型的唯一真相。端点地址本身必须来自可信配置或发现信息。




  3 验证“谁在请求、令牌是谁的”
    授权服务器验证客户端身份（或公共客户端所需信息），并核对该令牌是否发给这个客户端。这样不能任意拿
    一串猜测的令牌去撤销别人的授权。




  4 使令牌失效，并执行级联策略
    服务器使目标令牌不能再用。撤销 Refresh Token 时，若服务器支持 Access Token 撤销，应同时使同一授
    权下的 Access Token 失效；具体还可能处理授权总记录，取决于服务商策略。




  5 客户端停止使用，服务端逐步一致
    RFC 7009 规定收到 HTTP 200 后客户端不应继续用该令牌。分布式环境可能有传播延迟：有些资源服务器
    已经知道失效，有些尚未同步。




  6 后续访问被拒绝或要求重新授权
    在线校验令牌的资源服务器可立刻向授权服务器询问状态；离线校验的自包含 Access Token 可能依赖短有效
    期、黑名单/后端同步等设计。要恢复访问，用户通常需重新完成授权。
05 · 关键术语


把“撤销什么、谁来判断”说准确

Token Revocation 令牌撤销
专业解释：授权服务器的端点与状态改变机制，用于使一个令牌失效，并可按策略影响相关令牌或授权许可。
白话解释：去发卡处登记“这张钥匙以后作废”。
容易混淆：它不是把 App 图标删掉，也不必然删除第三方已经复制走的数据。



Authorization Grant 授权许可 / 授权总记录
专业解释：资源所有者给客户端的一次授权基础；令牌是由它派生的凭据。
白话解释：物业档案里那条“这个助手可读你的日历”的总许可。
容易混淆：它不等于某一张 Access Token；一份许可可关联多张令牌。



Refresh Token 刷新令牌
专业解释：客户端向授权服务器换取新 Access Token 的凭据，通常不能直接访问资源 API。
白话解释：能领新门卡的管理员钥匙。
容易混淆：撤销它不必然意味着每一张旧 Access Token 同时被所有资源服务器拒绝。



Propagation Delay 传播延迟
专业解释：授权状态变化从授权服务器传递到所有做访问判断的节点所需的时间窗口。
白话解释：总部已把卡作废，但某个远端闸机还没收到名单更新。
容易混淆：协议端点返回成功，与系统每个节点已经同步，是两件事。

08 · 常见误区


别把“协议成功”误读成“所有风险归零”
 常见说法：我删除了 App，所以授权一定没了。

 实际情况：删除本地 App 未必通知授权服务器，也未必使已发令牌失效。
 为什么：授权记录和令牌通常保存在服务端；需要产品提供移除访问的动作，或客户端主动调用撤销机制。




 常见说法：收到 HTTP 200，就表示每台服务器在同一刻拒绝旧令牌。

 实际情况：客户端应停止使用令牌，但分布式系统可能存在传播延迟。
 为什么：不同资源服务器可能缓存状态，或离线验证自包含 Access Token。




 常见说法：撤销 Refresh Token 必然立即杀死每一张 Access Token。

 实际情况：RFC 7009 说明这取决于撤销策略与是否支持 Access Token 撤销。
 为什么：Access Token 可以是在线可查询的句柄，也可以是资源服务器能离线验签的自包含令牌。




 常见说法：撤销后，第三方手里的历史数据也会自动被删除。

 实际情况：撤销主要阻断未来按授权访问；已经导出或复制的数据需要单独的数据删除与合规流程。
 为什么：访问控制与数据留存是两套不同的责任和技术机制。

10 · 三句话总结


记住这三句就抓住了核心
1. 令牌撤销是让授权服务器收回不再需要或有风险的凭据，尤其是能续发新令牌的 Refresh Token。

2. 它能让客户端停止使用令牌、阻止未来续发，并可能连带处理相关令牌或授权记录；级联范围由服务端策略决定。

3. 撤销不是数据删除，也不保证每个分布式节点同一毫秒完成同步；这正是短寿命令牌和在线/离线校验取舍存在的原
  因。




11 · 三道理解题


用自己的话检查是否真正理解
 1. 一句话题
 为什么卸载一个已连接云盘的 AI 助手，不等于撤销它的云盘访问？


 参考答案：卸载只改变本地设备；服务器仍可能保存授权记录和令牌。需要在账号连接管理中移除访问，或
 由客户端向授权服务器发起撤销。



 2. 边界题
 某系统撤销 Refresh Token 后，用户在几秒内仍用旧 Access Token 读到一次数据。这一定说明撤销失败吗？


 参考答案：不一定。可能是资源服务器尚未收到失效状态，或它离线验证短期 Access Token。应检查令牌寿
 命、校验模式、传播与撤销策略，而不是只看一次请求。



 3. 迁移题
 你在做一个“AI 自动整理客户邮件”的产品。用户点击“断开邮箱”时，除清除本地缓存外，至少还应设计哪两件
 事？


 参考答案：向身份提供方收回或撤销与该连接相关的凭据/许可，并阻止后台任务继续用旧令牌刷新；同时向
 用户说明已复制的数据如何保留、删除或导出。高敏场景还应记录审计事件并尽量缩短旧 Access Token 的
 可用窗口。
